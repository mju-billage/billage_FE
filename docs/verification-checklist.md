# 실기기 검증 체크리스트 — 6-A · 6-B · 7-A 누적

> 회비 조회(6-A) / 회비 생성(6-B) / 모임원 관리(7-A) 세 단계가 코드만 완성되고
> 한 번도 안 돌아본 상태다. 이걸 한 번에 확인한다.
>
> **고치지 말고 기록만 한다.** 발견한 걸 다 모아서 한 번에 처리하는 게 싸다.
>
> 심각도: **[치명]** 데이터가 틀리게 보이거나 저장 안 됨 · **[결함]** 동작은 하나 명세와 다름 · **[관찰]** 판단 필요

## A. 준비 — 안드로이드 실기기

### A-1. 기기 연결

| ☐ | 할 일 | 확인 |
|---|---|---|
| ☐ | 폰 설정 → 개발자 옵션 → **USB 디버깅** 켜기 | |
| ☐ | USB 연결 후 `adb devices` | 기기가 `device`로 나와야 함 |
| ☐ | `unauthorized`로 나오면 폰 화면의 **"USB 디버깅 허용"** 팝업 확인 | |
| ☐ | 시리얼 번호를 적어둘 것 → 아래에서 `$DEV`로 씀 | |

에뮬레이터도 같이 떠 있으면 **모든 adb 명령에 `-s $DEV`를 붙여야** 한다.
헷갈리면 에뮬레이터를 아예 끄는 게 편하다.

### A-2. 설치

```
npm start                                    # Metro (별도 터미널, 계속 켜둘 것)
npx react-native run-android --deviceId $DEV # 빌드 + 설치 + 실행
```

첫 빌드는 몇 분 걸린다. `INSTALL_FAILED_UPDATE_INCOMPATIBLE`이 뜨면
기존 앱을 지우고(`adb -s $DEV uninstall com.billage`) 다시.

### A-3. Metro 연결 — 실기기에서 제일 많이 막히는 곳

| ☐ | 할 일 | 확인 |
|---|---|---|
| ☐ | `adb -s $DEV reverse tcp:8081 tcp:8081` | **USB 연결이 끊기면 풀린다. 재연결할 때마다 다시** |
| ☐ | 앱 실행 → 빨간 에러 화면이면 위 명령 다시 | |

### A-4. 화면 밀도

| ☐ | 할 일 | 확인 |
|---|---|---|
| ☐ | `adb -s $DEV shell wm density` | 값을 적어둘 것 |

**480이 아니어도 이번 검증은 그대로 진행한다.** 기능·데이터 확인이 목적이라
밀도는 상관없다. 다만 **나중에 시안 대조용 스크린샷은 에뮬레이터(480)로 찍어야** 한다 —
실기기 캡처를 `shots/`에 넣지 말 것.

### A-5. 로그인

| ☐ | 할 일 |
|---|---|
| ☐ | **총무 계정**으로 로그인, `VerifyDues` 모임 진입 |

> `Step1Group` 계정은 무효다(2026-09-04 확인 — 서버에 이메일은 있으나 비밀번호를 잃어버렸고, 비밀번호
> 재설정 API도 없어 복구 불가). 새 계정 `billage.verify.dues.test@example.com`(비밀번호는 세션 내에서만
> 공유, `docs/api-integration-plan.md` "테스트 데이터 정책" 참고)이 총무로 있는 `VerifyDues` 모임
> (groupId 2, 장부 `VerifyLedger`, 모임원 `Verify1`)을 대신 쓴다.

## B. 모임원 만들기 — 7-A 검증

### B-1. 개별 추가 (전 필드 채우기)

경로: 더보기 → 모임 관리 → 모임원 관리 → 추가 → 개별 추가

| ☐ | 입력값 | 봐야 할 것 |
|---|---|---|
| ☐ | 이름 `김검증` | |
| ☐ | 전화번호 `010-1111-2222` | **숫자 키보드(phone-pad)가 뜨는가** |
| ☐ | 태그 3개 입력 | **3개 채우면 입력 필드가 막히는가** |
| ☐ | 태그 4개째 시도 | 안 들어가야 정상 |
| ☐ | 메모 아무거나 | 30자 넘으면 안 들어가야 함 |
| ☐ | 저장 | 스낵바 문구를 **그대로 적어둘 것** |

> 명세는 "{이름} 모임원이 추가되었어요"인데 목업은 이름 없이 고정 문구다.
> 구현은 목업을 따랐다. 실제로 뭐가 뜨는지 확인.

**나갔다 다시 들어와서 남아 있는지 확인** ← 저장이 진짜 됐는지 판정

전화번호 표기가 `010-1111-2222`로 보이는지도 확인 (서버는 숫자만 저장, 포맷은 앱이 함)

### B-2. 일괄 추가

경로: 모임원 관리 → 추가 → 일괄 추가

| ☐ | 입력 | 봐야 할 것 |
|---|---|---|
| ☐ | `이일괄, 박일괄 최일괄,정일괄` (쉼표·띄어쓰기 섞기) | |
| ☐ | 저장 | **4명으로 정확히 갈라졌는가** |
| ☐ | 목록 순서 확인 | 가나다순인가 (서버 정렬) |

> 이게 미검증 가정 1번이다. 클라이언트는 원문을 그대로 보내고 서버가 자른다고 가정했다.
> 쉼표만/띄어쓰기만/줄바꿈이 섞여도 되는지 확인.

### B-3. 검색

| ☐ | 확인 |
|---|---|
| ☐ | 검색창에 `일괄` 입력 → 4명만 남는가 |
| ☐ | **타이핑이 끊기지 않는가** (300ms 디바운스 넣음) |
| ☐ | 지우면 전체 목록 복귀 |

## C. 장부 · 회비 만들기 — 6-B 검증

### C-1. 장부 확인

| ☐ | 확인 |
|---|---|
| ☐ | 폴더 탭에 장부가 있는가 |
| ☐ | 없으면 폴더/장부 생성 (3-B에서 붙인 화면) |

### C-2. 회비 생성 ①  오늘 시작 · 마감일 가까운 것

경로: 납부관리 탭 → `+`

| ☐ | 입력 | 봐야 할 것 |
|---|---|---|
| ☐ | 제목 `테스트회비A` | 20자 넘으면 안 들어가야 함 |
| ☐ | 금액 `30000` | |
| ☐ | 금액에 `9999999999` 시도 | **999,999,999에서 멈추는가** |
| ☐ | 장부 선택 | 기존 시트 재사용 — 정상 뜨는가 |
| ☐ | 기간 = **시작일 오늘 / 마감일 3일 뒤** | 범위 캘린더에서 두 날짜 다 찍어야 다음 단계 활성화되는가 |
| ☐ | 모임원 선택 → 전체 선택 | **검색 필터 걸린 상태에서 전체선택하면 필터된 것만 되는가** |
| ☐ | 생성 | 스낵바 → 목록에 바로 보이는가, **400 없이 성공하는가**(2026-09-05 이전엔 여기서 항상 400이었음) |

> **기간 입력란이 이제 있다** — 2026-09-05에 명세대로 복원했다. 시작일도 실제로 서버에 전송된다.

### C-3. 회비 생성 ②  미래 시작 · 마감일 먼 것

| ☐ | 제목 `테스트회비B`, 금액 `50000`, 기간 = **시작일 7일 뒤 / 마감일 30일 뒤**, 모임원 2명만 |

> 이 회비는 시작일이 미래라 D절에서 `SCHEDULED`로 보여야 한다 — ①(오늘 시작)과 비교할 대상.

### C-4. 이탈 방지

| ☐ | 확인 |
|---|---|
| ☐ | 회비 생성 화면 열고 **아무것도 안 건드리고** X → 바로 나가지는가 |
| ☐ | 제목만 입력하고 X → "그만둘까요?" 모달이 뜨는가 |

## D. 회비 화면 확인 — 6-A 검증

### D-1. SCHEDULED / OPEN 상태 확인

2026-09-05에 상태 판정을 서버 `status` 그대로 쓰도록 고쳤다(예전엔 `paidCount===0`으로
"예정"을 잘못 추정했다 — 아무도 안 낸 것과 시작 전인 것을 구분 못 했던 버그, 지금은 서버가
`SCHEDULED`를 직접 준다). 이 절은 그 수정이 실기기에서도 맞는지 확인한다.

| ☐ | 확인 |
|---|---|
| ☐ | ①(오늘 시작, C-2)이 목록에서 **D-day 배지**(`D-3` 등)로 보이는가 — "예정" 아님 |
| ☐ | ②(7일 뒤 시작, C-3)가 목록에서 **"MM.DD D-N" 형태**(시작일 + 시작까지 남은 일수)로 보이는가 |
| ☐ | 둘의 배지 색이 다른가(①은 D-day 임박도 색, ②는 중립색) |

> 만약 둘 다 같은 표시로 보이거나 ②가 D-day로 보이면 상태 판정이 아직도 틀린 것 — **[치명]**.
> 정확히 어떻게 보이는지 적어둘 것.

### D-2. 목록 카드

| ☐ | 확인 |
|---|---|
| ☐ | D-day 배지 — 3일 뒤 회비와 30일 뒤 회비의 **색이 다른가** |
| ☐ | 납부 인원 `0/5명` 형태로 맞는가 |
| ☐ | 금액 `0원 / 150,000원` — **모임원 수 × 회비 금액**이 맞는가 |
| ☐ | 진행률 바가 0%인가 |
| ☐ | 목록 건수 텍스트 ("2 건") |
| ☐ | 탭 `전체` / `진행중` 전환이 되는가 |

### D-3. 회비 상세

| ☐ | 확인 |
|---|---|
| ☐ | 카드 탭 → 상세 진입 |
| ☐ | **"납부 기간" 시작일이 실제로 입력한 시작일과 같은가**(2026-09-05부터 `startDate` 그대로 표시 — 예전엔 생성일로 대체돼 있었음) |
| ☐ | ②(SCHEDULED)의 상세 상단 배지가 시작일 날짜로 보이는가 |
| ☐ | 모임원별 납부 현황 목록에 대상자가 다 나오는가 |
| ☐ | 기본으로 열리는 탭이 `미납부`인가 |

### D-4. 대시보드 반영

| ☐ | 확인 |
|---|---|
| ☐ | 홈 탭 → 회비 섹션이 "진행 중인 회비가 없어요"에서 실제 데이터로 바뀌었는가 |
| ☐ | 요약(수입/지출/잔액)이 뜨는가 |

## E. 권한 확인 — 일반 계정

`Step2Mem`도 `Step1Group`과 묶여 있던 계정이라 같이 무효했다. 2026-09-05에 새 MEMBER 계정을
만들어 `VerifyDues`(groupId 2)에 초대코드로 참여시켰다(`membershipId: 5`, `role: MEMBER`,
`GET /groups/2/memberships`로 확인 완료) — 아래 계정으로 재로그인하면 된다.

`billage.verify.member.test@example.com` / 비밀번호 `Billage1!Member` 로 재로그인

| ☐ | 확인 | 기대 |
|---|---|---|
| ☐ | 납부관리 메인의 `+` | **안 보여야 함** |

| ☐ | 모임원 **전화번호** | **보여야 함** (기획 확정: 일반도 조회 가능) |

## F. 실패 경로

| ☐ | 상황 | 봐야 할 것 |
|---|---|---|
| ☐ | 이름 11자 입력 | 입력 자체가 막히는가 |

| ☐ | 모임원 전원 삭제하고 회비 생성 시도 (7-B 전이라 삭제 불가면 생략) | 빈 상태 안내 |
