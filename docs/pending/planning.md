# 기획 확인 대기

정책·동작·권한·흐름 결정이 필요해서 기획에게 물어야 하는 것들.

---

## 1. 내역 수정·삭제·승인 권한 — 일반 권한 관리자 배제

**현상/생긴 경위**

시안/요구는 "삭제 아이콘 항상 노출", "승인 요청은 관리자가 들어가서 바로 수정"
인데, Entry API 는 수정·삭제·승인 모두 OWNER(총무)만 허용한다(일반 권한
관리자가 자기 승인 대기 내역도 수정 못 함, 2026-08-17 확정). QA-038 에서는
API 기준대로 OWNER 에게만 앱바 아이콘(수정/삭제)과 승인하기 버튼을 노출했다.

**물어볼 것**

기획 의도가 "모든 관리자(MEMBER 포함)" 였다면 백엔드와 함께 권한을 넓혀야
한다. 지금 구현은 임의로 열지 않았다.

**답이 오면 할 일**

권한을 넓히기로 하면 `src/screens/Folder/TransactionDetailScreen.tsx` 의
OWNER 체크 조건을 넓혀야 한다. Entry API 쪽 권한 정책도 같이 바뀌어야 해서
`docs/pending/backend.md` 쪽 작업으로도 이어진다.

---

## 2. MEMBER가 승인 대기 내역을 눌렀을 때의 화면/동작

**현상/생긴 경위**

QA-038 로 MEMBER(일반 권한 관리자)는 내역 상세에서 앱바 아이콘·승인하기
버튼이 전부 사라진다. 조회만 가능한 화면이 맞는지, 아니면 "검토 요청" 같은
별도 동작이 있어야 하는지가 시안에 없다.

**물어볼 것**

MEMBER가 승인 대기 내역을 봤을 때 기대 동작.

**답이 오면 할 일**

정해진 동작에 맞춰 `src/screens/Folder/TransactionDetailScreen.tsx` 에 MEMBER
전용 분기(별도 버튼/안내 등)를 추가한다.

## 3. 캘린더 경로(hideActions)에서 숨길 범위

**현상/생긴 경위**

QA-038 은 "대시보드 미니캘린더 → CalendarScreen → 상세" 경로에서 앱바
아이콘만 숨겼다(hideActions). 행 수정 화살표, 사진 추가/삭제, 승인하기 버튼은
그대로 노출된다.

**물어볼 것**

이 경로로 들어왔을 때 행 수정 화살표·사진 추가/삭제·승인하기 버튼도 같이
숨겨야 하는지.

**답이 오면 할 일**

숨기기로 하면 `src/screens/Folder/TransactionDetailScreen.tsx` 의
`hideActions` 조건을 행별 수정·증빙 추가/삭제·승인하기 버튼에도 적용한다.
