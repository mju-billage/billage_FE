# 캡처 진입 경로 (shot-targets.tsv 대응)

`docs/design-verification.md` §2 + `scripts/shot-targets.tsv` 대상 76개 Screen ID의 실제 진입 경로.
근거는 `RootNavigator.tsx` / `MainTabNavigator.tsx` / `FolderTabNavigator.tsx`의 라우트 정의와 각 화면
코드의 `navigation.navigate(...)` 호출부, 그리고 바텀시트/다이얼로그를 여는 로컬 state다. 코드에서
확인 안 되는 것은 추측하지 않고 "경로 불명"으로 남겼다.

도메인별로 묶고, 한 화면에 들어가서 연달아 찍을 수 있도록 같은 플로우를 순서대로 배열했다.

범례: **[자동소멸]** = 일정 시간 뒤 사라지는 스낵바, 캡처 타이밍 맞춰야 함. **[상태변형]** = 같은 화면의
서로 다른 상태(빈 값/입력중/에러 등)를 나타내는 하위 항목.

---

## 캡처 전 확인

파일럿(5개) 진행 중 Metro 미기동으로 앱이 빨간 에러 화면만 뜨는 상태에서 캡처를 시작해 시간을 날린
적이 있다. 매 캡처 세션 시작 전에 아래를 순서대로 확인해라.

1. **Metro 번들러 기동 확인**: `netstat -ano | grep "127.0.0.1:8081.*LISTENING"` 로 이미 떠 있는지 먼저
   확인. 안 떠 있으면 `npm start`를 백그라운드로 기동하고 `LISTENING` 뜰 때까지 기다려라.
2. **`adb reverse tcp:8081 tcp:8081`**: 에뮬레이터를 새로 띄웠거나 `adb kill-server`를 거쳤으면 리버스
   포워딩이 끊겨 있다. 캡처 세션 시작 시 한 번 걸어두고, **`adb shell pm clear com.billage`로 앱 데이터를
   초기화한 뒤에도 다시 확인해라** — `pm clear`는 reverse 설정 자체를 지우지 않지만, 클리어 전후로
   에뮬레이터를 재기동했거나 `adb` 서버가 재시작된 경우엔 같이 끊겨 있을 수 있다. 앱을 새로 실행한 뒤
   빨간 에러 화면이 뜨면 이것부터 의심해라.
   (2026-08-28 COM 배치 캡처 중 실측: 같은 emulator+adb 세션 안에서 `pm clear`만 단독으로 실행했을
   땐 reverse가 끊기지 않았다 — 에뮬레이터/adb 서버 자체를 안 건드렸으면 `pm clear` 후 매번 다시
   걸 필요는 없어 보인다. 그래도 앱 재실행 직후 빨간 에러 화면이 뜨면 1번으로 돌아가 확인해라.)
3. **밀도 확인**: `adb shell wm density` → 480 기대. `adb shell wm size` → 1080x2340 기대. 다르면
   여백·폰트 비교가 무의미해지니 여기서 멈추고 AVD 프로필을 확인해라.
4. **위 둘 다 정상인데 여전히 빨간 에러 화면**이면 다른 원인(빌드 자체 실패, JS 런타임 에러)이니
   `adb logcat`이나 Metro 콘솔 로그를 봐라.
5. **RN 개발 모드 배너("Open debugger to view warnings.")를 닫고 캡처해라.** 화면 하단(바텀시트/탭바
   근처)을 가려서 대조가 불가능해지는 경우가 있었다(2026-08-28 COM/DSH 배치, `design-diff.md`의
   DSH-1-PAGE-01-0 참고 — 배너 때문에 콘텐츠 존재 여부조차 확인 못 함). 배너 우측 X를 탭해 닫거나,
   가능하면 캡처 전 `LogBox.ignoreAllLogs()`류로 아예 안 뜨게 하는 걸 검토해라.

## COM — 로그인/회원가입

전부 **로그아웃 상태**여야 도달 가능. 이미 로그인돼 있으면 앱 재설치하거나 로그아웃 기능이 없으므로
`adb shell pm clear com.billage`로 세션을 지우고 시작해라.

1. **`COM-1-PAGE-01-0`** 로그인 — 권한: 전체
   경로: 앱 최초 실행(비로그인 상태) → 로그인 화면이 첫 화면.

2. **`COM-2-PAGE-01-0`** 약관 동의 — 권한: 전체
   경로: 로그인 → 하단 "회원가입하기" 버튼.

3. **`COM-3-PAGE-01-0`** 약관 상세 — 권한: 전체 — **[상태변형]** 3개 파일(서비스 이용약관/개인정보처리방침/마케팅동의)
   경로: 약관 동의 화면 → 각 항목 옆 ">" 아이콘(서비스 이용 약관 / 개인정보 수집 및 이용 / 마케팅 정보 수신 동의 각각).

4. **`COM-3-PAGE-03-0`** 가입 정보 입력 — 권한: 전체
   경로: 약관 동의 → 필수 항목 체크 → "다음으로".

5. **`COM-4-PAGE-01-0`** 이메일 인증 — 권한: 전체
   경로: 가입 정보 입력 → 이메일/비밀번호/이름 입력 → 제출.

6. **`COM-5-PAGE-01-0`** 가입 완료 — 권한: 전체
   경로: 이메일 인증 → 인증코드 입력 → 확인.

7. **`COM-3-PAGE-02-0`** 간편 가입 정보 입력 — 권한: 전체
   경로: 로그인 화면 → 카카오(K)/네이버(N)/구글(G) 소셜 로그인 버튼. 실제 SDK 연동이라 각 provider
   로그인이 실제로 성공해야 진입한다 — mock 계정으로는 재현이 안 될 수 있음.

8. **`COM-2-PAGE-02-0`** 비밀번호 재설정 — 권한: 전체
   경로: 로그인 화면 → "비밀번호를 잊으셨나요?".

9. **`COM-3-PAGE-04-0`** 비밀번호 재설정_완료 — 권한: -
   경로: 비밀번호 재설정 → 이메일 입력 → 제출.

   재현할 상태: 상태 불명 (디자인 후보 6장, 두 폴더에 걸쳐 있어 사전 확인 생략).

   재현할 상태: 상태 불명 (디자인 후보 9장, 세 폴더에 걸쳐 있어 사전 확인 생략).

4. **`DTB-3-SHEET-02-0`** 장부 복수 선택 — 권한: 전체
   경로: 내역 필터링 시트 → "+ 장부" 칩.
   재현할 상태: 장부 6개(MT/총회/정기훈련/대회/비품구매/동아리지원금) 목록, 아무것도 선택 안 된
   기본 상태(선택하기 버튼 비활성).

5. **`DTB-2-PAGE-01-0`** 내역 검색_전체 — 권한: 전체
   경로: 내역 메인 → 검색(돋보기) 아이콘.
   재현할 상태: 검색어 비어있음, 기본 내역 6건 이상(승인요청 배지 포함) 그대로 표시된 상태
   (검색 결과 아님 — 검색창만 뜨고 목록은 그대로인 초기 상태로 보임).

6. **`DTB-2-PAGE-02-0`** 상세 내역_조회 — 권한: 전체
   경로: 내역 메인/내역 검색/장부 상세/장부 내역검색 중 아무 목록에서나 행 탭 → `TransactionDetail`.
   재현할 상태: 상태 불명 (디자인 후보 6장, 두 폴더에 걸쳐 있어 사전 확인 생략).

7. **`DTB-3-MODAL-01-0`** 상세 내역_삭제 — 권한: 전체
   경로: 상세 내역_조회 → 우상단 삭제 아이콘.
   재현할 상태: **디자인 이미지가 의심스럽다** — 열어보니 삭제 확인 다이얼로그가 아니라 "상세 내역"
   타이틀에 본문이 완전히 빈 화면 + "등록하기" 버튼만 있다. 상세 내역_삭제 모달 디자인이 아니라
   다른 화면(등록 관련)이 잘못 파일링됐을 가능성 — 캡처해서 실제로 뭐가 뜨는지 비교하되, 대조는
   "상태 불명"으로 처리하고 기획 쪽에 이 디자인 파일 자체를 재확인 요청할 것.

8. **`DTB-3-PAGE-02-0`** 상세 내역_수정 — 권한: 전체 — **경로 불명(연결 안 됨)**
   상세 내역_조회 화면의 수정 아이콘이 `onPress: () => {}`라 실제로 도달할 방법이 없다.
   `docs/design-verification.md`에 남긴 대로 DTB/폴더 거래 데이터소스 병합 후 연결 예정.
   재현할 상태: 해당 없음 (디자인 이미지 자체가 없음 — design-index.json에 항목 없음).

9. **`DTB-4-MODAL-01-0`** 상세 내역_수정 이탈 안내 — 권한: 전체
   경로: ADD 쪽 `ADD-2-MODAL-01-0`과 코드가 완전히 같은 모달(`TransactionRegisterScreen.tsx` 이탈 다이얼로그).
   "상세→수정"이 연결 안 돼 있어서 지금은 **ADD-1-PAGE-01-0 경로로만** 도달 가능하다(아래 참고).
   재현할 상태: 해당 없음 (디자인 이미지 자체가 없음 — `ADD-2-MODAL-01-0`으로 대체 캡처).

   재현할 상태: "여기로 이동하기" 버튼 비활성(회색), 이동 대상으로 고른 폴더(1학기)와 그 하위

## 참고: 총무 계정 vs 일반 계정

현재 로그인은 "목 계정으로 로그인 (개발용)" 버튼 하나뿐이라 계정을 바꿔 총무/일반을 나눠 로그인하는
기능 자체가 안 보인다. `ETC` 도메인의 "타인 프로필이 총무냐 일반이냐"(9/10번)는 **모임원 목록에서
어떤 행을 탭하느냐**로 갈리는 것이지 내 계정 권한이 아니다. "일반" 전용 2건(`ETC-3-MODAL-01-0`,
`ETC-3-MODAL-01-1`)도 마찬가지로 "본인 행"을 탭하면 되고 별도 로그인이 필요 없다. `총무` 권한
행(21건, FDR 대부분)은 지금 mock 데이터의 로그인 계정이 총무 역할이라 그대로 캡처 가능해 보이나,
`types/group.ts`의 `isMe` 목업이 실제로 총무인지는 캡처 직전에 화면에서 눈으로 확인해라.
