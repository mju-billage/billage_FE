# 캡처 진입 경로 (shot-targets.tsv 대응)

`docs/design-verification.md` §2 + `scripts/shot-targets.tsv` 대상. **2026-09-11 전면 재생성** —
지난 버전은 76개 기준이었다. 지금은 `[구현]` 124개(+ IA 비정규 3개 포함 총 127개, `screen-audit`
스크립트가 찾아낸 것들) 전부가 대상이다.

근거는 `RootNavigator.tsx` / `MainTabNavigator.tsx` / `FolderTabNavigator.tsx`의 라우트 정의와 각 화면
코드의 `navigation.navigate(...)` 호출부, 그리고 바텀시트/다이얼로그를 여는 로컬 state다. 코드에서
확인 안 되는 것은 추측하지 않고 "상태 불명"으로 남겼다.

범례: **[자동소멸]** = 일정 시간 뒤 사라지는 스낵바, 캡처 타이밍 맞춰야 함. **[상태변형]** = 같은 화면의
서로 다른 상태(빈 값/입력중/에러 등)를 나타내는 하위 항목 — 별도 네비게이션 없이 같은 화면 안에서
탭/상태를 바꿔서 찍는다. **[총무]**/**[일반]** = 권한별로 계정을 나눠 찍어야 하는 화면.

우선순위 묶음은 바로 아래 "우선순위 묶음" 절 참고 — 도메인 순서가 아니라 **찍는 순서**는 그쪽을 따라라.
이 문서 본문은 도메인별로 정리해뒀을 뿐이다(참고하기 쉬우라고).

## 캡처 전 확인

파일럿(5개) 진행 중 Metro 미기동으로 앱이 빨간 에러 화면만 뜨는 상태에서 캡처를 시작해 시간을 날린
적이 있다. 매 캡처 세션 시작 전에 아래를 순서대로 확인해라.

1. **Metro 번들러 기동 확인**: `netstat -ano | grep "127.0.0.1:8081.*LISTENING"` 로 이미 떠 있는지 먼저
   확인. 안 떠 있으면 `npm start`를 백그라운드로 기동하고 `LISTENING` 뜰 때까지 기다려라.
2. **`adb reverse tcp:8081 tcp:8081`**: 에뮬레이터를 새로 띄웠거나 `adb kill-server`를 거쳤으면 리버스
   포워딩이 끊겨 있다. 캡처 세션 시작 시 한 번 걸어두고, **`adb shell pm clear com.billage`로 앱 데이터를
   초기화한 뒤에도 다시 확인해라.**
3. **밀도 확인**: `adb shell wm density` → 480 기대. `adb shell wm size` → 1080x2340 기대. 다르면
   여백·폰트 비교가 무의미해지니 여기서 멈추고 AVD 프로필을 확인해라.
4. **위 둘 다 정상인데 여전히 빨간 에러 화면**이면 다른 원인(빌드 자체 실패, JS 런타임 에러)이니
   `adb logcat`이나 Metro 콘솔 로그를 봐라.
5. **RN 개발 모드 배너("Open debugger to view warnings.")를 반드시 닫아라.** 화면 하단(바텀시트/탭바
   근처)을 가려서 대조가 불가능해지는 경우가 실제로 있었다(2026-08-28 COM/DSH 배치). 배너 우측 X를
   탭해 닫거나, `App.tsx` 최상단에 `LogBox.ignoreAllLogs()`를 임시로 추가해 아예 안 뜨게 해라 — 캡처가
   끝나면 그 줄은 지운다(커밋에 남기지 말 것).
6. **테스트 계정 상태를 세션 시작 전에 정해라.** 이번 배치는 총무/일반 두 계정을 오가야 하는 화면이
   많다(아래 "권한별 계정" 절 참고). 계정 전환은 로그아웃(더보기 → 내 프로필 → 로그아웃) 후 재로그인
   뿐이다 — 세션 하나에서 총무 화면 찍고 로그아웃 → 일반 계정 로그인 → 일반 화면 찍는 순서로 묶으면
   전환 횟수를 줄일 수 있다.

## 권한별 계정

`총무`/`일반` 둘 다 필요한 화면은 각 도메인 절에 **[총무]**/**[일반]** 표시를 따로 달아뒀다. 계정
전환은 로그아웃 후 재로그인뿐이다(소셜/이메일 어느 쪽이든 총무·일반 각 1계정씩 미리 준비해두는 걸
권장). 모임 나가기(`ETC-3-MODAL-01-0`/`01-1`)와 알림 설정(`ETC-3-PAGE-08-0`)은 반드시 계정을 바꿔서
찍어야 한다 — "본인 행"을 눌러 재현하는 게 아니라 **로그인 계정 자체의 역할**로 갈린다(전자는 모임
안에서 본인이 유일한 총무인지가 기준, 후자는 `getActiveGroup()?.myRole` 자체가 기준).

## COM — 로그인/회원가입/탈퇴

전부 **로그아웃 상태**여야 도달 가능한 COM-1~5는 기존과 동일(로그인/약관/가입/이메일인증 등, 이번
배치 대상 아님 — 이미 캡처됨). 탈퇴 4종은 **로그인 상태**에서 진입한다.

1. **`COM-1-PAGE-02-0`** 탈퇴_안내사항 — 권한: 전체
   경로: 더보기 → 내 프로필(`MyProfileScreen`) → "탈퇴하기".
   재현할 상태: 유의사항 불릿 6개, "확인했어요" 버튼. 화면 진입 시 유일 총무 모임을 미리 조회하므로
   로딩 상태가 잠깐 보일 수 있음.

2. **`COM-2-PAGE-04-0`** 탈퇴_권한 넘기기 — 권한: 전체 — **[Case A 전용]**
   경로: 탈퇴_안내사항 → "확인했어요" (계정이 유일한 총무인 모임을 1개 이상 갖고 있을 때만 이 화면).
   재현할 상태: 유일 총무 모임마다 새 총무 후보 리스트, 아무도 선택 안 된 상태(제출 버튼 비활성) +
   1명씩 선택한 상태(활성) 둘 다 찍어라. **테스트 계정이 유일 총무인 모임을 미리 만들어둬야 한다.**

3. **`COM-2-PAGE-05-0`** 탈퇴_사유 입력 — 권한: 전체
   경로 (a): 탈퇴_안내사항 → "확인했어요" (유일 총무 모임이 없을 때, [Case B]).
   경로 (b): 권한 넘기기 → "권한 넘겨주기" (모든 모임 위임 완료 후).
   재현할 상태: 체크박스 5개(사용법을 모르겠어요/다시 가입할 거예요/원하는 기능이 없어요/이용할
   필요가 없어졌어요/직접 입력할게요), "직접 입력할게요" 체크 시 아래 텍스트 필드 노출.

4. **`COM-3-MODAL-01-0`** 탈퇴_사유 입력(최종 확인 모달) — 권한: 전체
   경로: 탈퇴_사유 입력 → 사유 1개 이상 선택 → "탈퇴하기".
   재현할 상태: "정말 탈퇴하시겠어요?" + "탈퇴 시 모든 정보와 이용 내역이 삭제돼요." 2버튼(취소/탈퇴하기,
   destructive). **"탈퇴하기"를 실제로 누르지는 마라** — 서버가 `DELETE /auth/me`를 미구현이라 에러가
   뜰 텐데, 모달 자체는 그 전에 캡처 가능하다.

## 참고: 총무 계정 vs 일반 계정

"목 계정으로 로그인" 버튼은 이제 없다 — 실제 이메일/소셜 로그인만 있다. 총무 1개·일반 1개, 최소
두 계정을 미리 준비해라. 유일 총무 모임이 필요한 탈퇴 플로우(`COM-2-PAGE-04-0`)를 위해 **총무
계정 중 하나는 다른 관리자가 없는 모임을 최소 1개 갖고 있어야** 한다 — 미리 만들어둘 것.
